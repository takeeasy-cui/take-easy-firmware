## 1. 引擎整体介绍

### 1.1 架构总览

```
┌────────────────────────────────────────────────────────────┐
│ 应用页（main/apps/app_apps.c）                              │
│   ┌─────────┐ ┌─────────┐ ┌─────────┐                      │
│   │推理游戏  │ │文字游戏  │ │步步高游戏│   ← 三个 APP 入口    │
│   └────┬────┘ └────┬────┘ └────┬────┘                      │
│        │ app_avgr.c│ app_gtext.c │ app_gbbk.c（薄壳≈50行） │
└────────┼───────────┼────────────┼──────────────────────────┘
         └───────────┴─────┬──────┘
                           ▼
┌────────────────────────────────────────────────────────────┐
│ GameCore 统一游戏内核（main/game/）           ← 你只对接这里 │
│  game_core.c   互斥实例 · 输入路由 · 刷新裁决 · 桥接        │
│  game_pkg.c    分类扫包 · zip 解挂 · 目录直挂              │
│  game_host_ui.c共享绘制原语（对话框/按钮/标题/打字机/贴图） │
├────────────────────────────────────────────────────────────┤
│ 插件（main/apps/plugins/）                  ← 你要写的部分  │
│  avgr.c  推理 AVG（复用 components/avg_engine 业务引擎）    │
│  gtext.c 通用文字游戏（自带极简脚本解释器）                 │
│  gbbk.c  步步高 BBK（骨架，FMJ 引擎接入中）                 │
├────────────────────────────────────────────────────────────┤
│ 平台服务（插件只可调用，不可绕过）                           │
│  ui_kit / epdiy 绘制原语 · book_image 图片灰度解码          │
│  zip_reader 只读 ZIP · read_pico_buzzer 蜂鸣 · VFS(fatfs)  │
└────────────────────────────────────────────────────────────┘
```

**设计三原则**（开发时据此自检）：
1. **主引擎至上**：生命周期、运行互斥、资源包装载、输入分发、刷新策略、共享观感全部在内核；插件只剩游戏逻辑。
2. **最大化复用**：ZIP 复用 EPUB 的 `zip_reader`；图片解码复用书籍管线的 `book_image_file_*`；界面原语复用 `game_host_ui`。插件不要重造任何轮子。
3. **互斥运行**：同一时刻只有一个插件实例存活。启动新插件时内核先完整卸载上一个（quit + PSRAM 归还 + 包卸载），不存在并发与内存竞争。

### 1.2 运行时序（一个插件的一生）

```
用户在应用页点入口
  └→ 薄壳 on_enter → gc_launch(插件)
       ├→ gc_shutdown()         # 如有在跑插件：quit + 卸载包
       ├→ gc_pkg_scan/mount     # 扫 /sdcard/games/<前缀>-*；zip 解压到 /sdcard/.gcache/
       ├→ 插件.launch(pkg_dir)  # 插件建会话 State，返回 false=走引导页
       └→ 每帧循环：
            gc_app_tick   → 插件.tick()   # 打字机/动画（时间在 g->app->now_ms）
            gc_app_gesture→ 插件.input()  # 已识别手势（TAP/SWIPE）
            gc_app_key    → 插件.key()    # KEY1；KEY2=内核强刷；右键/中长按=内核退出
            回报 GC_EV_*  → 内核换算 APP_REDRAW_* 按申报区域差分刷屏
  用户退出（右键 / 中键长按 / TF 失效）
  └→ gc_shutdown → 插件.quit()  # 归还全部内存，置 g->state=NULL
```

### 1.3 输入与刷新（内核固定的恒语义）

输入（**不可改**，全线游戏一致）：

| 操作 | 行为 |
|---|---|
| 中键短按 | 整屏强刷（内核处理，插件不感知） |
| 中键长按 | 退出游戏回应用页（内核处理，插件不感知） |
| 右键 | 退出（内核处理） |
| 左键（KEY1） | 插件自定义（`key` 回调，典型=推进/确认） |
| 触摸手势 | `input` 回调，收到已识别的 TAP/SWIPE_* |

刷新（**申报制**，墨水屏不做无意义整刷）：
- 插件每轮把变化画进 `g->app->fb`，并置 `g->area`（变化矩形）、`g->want_full`（是否需整屏 GC16），返回 `GC_EV_DIRTY`；
- 内核把申报换算成 `APP_REDRAW_AREA`（差分 GL16）或 `APP_REDRAW_FULL`；
- 无变化返回 `GC_EV_NONE`，一帧不刷。

## 2. 插件抽象接口定义

接口全部在 `main/game/game_core.h`（唯一需要 include 的内核头）。

### 2.1 插件结构 `gc_plugin_t`

```c
typedef struct gc_plugin_s {
    const char* id;     /* 固定标识："avgr""text""bbk"，小写英文 */
    const char* name;   /* 应用页 tile 显示名 */
    gc_cat_t    cat;    /* 分类（决定扫包前缀与入口归属） */

    bool   (*launch)(gc_ctx_t* g, const char* title_arg);
    void   (*quit)(gc_ctx_t* g);
    void   (*paint)(gc_ctx_t* g, uint8_t* fb);
    gc_ev_t (*input)(gc_ctx_t* g, const ui_gesture_event_t* ev);
    gc_ev_t (*key)(gc_ctx_t* g, int key);
    gc_ev_t (*tick)(gc_ctx_t* g);
} gc_plugin_t;
```

**回调契约**（逐字段）：

| 回调 | 时机 | 必须做 | 禁止做 |
|---|---|---|---|
| `launch` | 进入口一次 | `calloc` 会话挂 `g->state`；读资源建游戏数据；首帧状态就绪 | 任何绘制（还没画布）；I2C/音效副作用 |
| `quit` | 退出/被顶替/TF 失效/`launch` 成功前的任何失败路径 | 释放**全部**堆与 PSRAM；`g->state=NULL` | 遗漏任何 malloc（内核不替你收尾） |
| `paint` | 每次重绘（含强刷） | 纯绘制；`g->state==NULL` 时画引导页（`gc_ui_nopkg`） | 文件 IO、蜂鸣、日志刷屏之外的副作用 |
| `input` | 已识别手势 | 命中测试→推进游戏→申报刷新 | 长耗时 IO（>50ms 会掉帧感） |
| `key` | KEY1 | 同上 | 处理 KEY2/KEY3（内核已用） |
| `tick` | 每主循环帧 | 打字机/动画推进，限频节流 | 每帧无条件申报刷新 |

字段全可空（NULL）：骨架插件可以只实现 `launch/quit/paint`（如 gbbk.c）。

### 2.2 运行上下文 `gc_ctx_t`（launch 时内核填好，插件保存）

```c
typedef struct {
    app_ctx_t*         app;      /* fb / hl / now_ms / request_* */
    const gc_plugin_t* plugin;   /* 自己 */
    char pkg_name[48];           /* 包名（去前缀去 .zip，如 gyakuten-case1） */
    char pkg_dir[192];           /* 已挂载资源根目录；""=无包（paint 画引导页） */
    void* state;                 /* 插件私有状态指针 */
    EpdRect area;  bool want_full;  /* 刷新申报（回调自行置位） */
} gc_ctx_t;
```

**关键规则**：`state != NULL` 才会收到 `input/key/tick`；`launch` 失败请确保 `state=NULL`（引导页可画、输入可忽略），或干脆 launch 前 malloc 失败直接 `return false`（内核会清 state）。

### 2.3 事件返回值 `gc_ev_t`

```c
GC_EV_NONE    /* 无变化，不刷屏 */
GC_EV_DIRTY   /* 按 g->area / g->want_full 申报刷新 */
GC_EV_PAGE    /* 整页重画（APP_PAGE_REFRESH_MODE） */
GC_EV_QUIT    /* 插件主动请求退出（罕见，如通关后） */
```

### 2.4 屏幕几何

- 逻辑坐标恒为**竖屏 684×1216**（x 右 y 下）；内核/共享 UI 均用此坐标。
- 对话框版式参考（与现役游戏一致）：场景区 0..840，对话框 840..1216，正文 4 行 × 20 宽度单位（中文=2 单位）。
- 颜色：8bit 灰（0=纯黑，255=纯白）；贴图统一走 `gc_ui_blit_gray`（自动 16 级抖动）。

## 3. 插件代码规范

### 3.1 目录与命名

```
main/apps/plugins/
  ├── <plugin>.c          # 实现文件（小写，与 id 同名）
  └── <plugin>.h          # 只导出一行：extern const gc_plugin_t gc_plugin_<id>;
```

- 插件内部符号一律 `static`；对外只暴露 `gc_plugin_<id>` 一个。
- 状态结构命名 `<id>_state_t`，集中放文件头；**全部指针成员在 quit 中释放**。
- 文件头注释三行：插件职责 / 复用了哪些引擎能力 / 资源包格式。

### 3.2 最小可用插件（可直接拷贝改名编译）

```c
/* plugins/hello.c — 最小示例：读包内 hello.txt 首行做打字机展示。 */
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#include "ui_kit.h"
#include "ui_menu.h"
#pragma GCC diagnostic ignored "-Wformat-truncation"   /* 路径拼接豁免（惯例）*/

#include "game_core.h"

typedef struct { char text[256]; int shown; int64_t last_ms; } hello_state_t;

static void draw_line(void* user, const char* line, int y) {
    ui_text_vc((uint8_t*)user, 48, y, 28, line, EPD_DRAW_ALIGN_LEFT, false);
}

static void paint(gc_ctx_t* g, uint8_t* fb) {
    hello_state_t* s = (hello_state_t*)g->state;
    if (!s) { gc_ui_nopkg(fb, "Hello 游戏", GC_CAT_TEXT); return; }
    gc_ui_dialog_frame(fb, 840);
    gc_ui_name_tag(fb, 840, "示例");
    gc_ui_typewrap(s->text, s->shown, 4, 20, draw_line, fb, 886, 44);
}

static bool launch(gc_ctx_t* g, const char* title_arg) {
    (void)title_arg;
    hello_state_t* s = calloc(1, sizeof(hello_state_t));
    if (!s) return false;
    g->state = s;
    snprintf(s->text, sizeof(s->text), "（无文本）");
    if (g->pkg_dir[0]) {
        char path[224];
        snprintf(path, sizeof(path), "%s/hello.txt", g->pkg_dir);
        FILE* f = fopen(path, "r");
        if (f && fgets(s->text, (int)sizeof(s->text), f)) { /* 首行即文本 */ }
        if (f) fclose(f);
    }
    return true;
}

static void quit(gc_ctx_t* g) { free(g->state); g->state = NULL; }

static gc_ev_t tick(gc_ctx_t* g) {
    hello_state_t* s = (hello_state_t*)g->state;
    size_t total = strlen(s->text);
    if ((size_t)s->shown >= total) return GC_EV_NONE;
    if (g->app->now_ms - s->last_ms < 60) return GC_EV_NONE;   /* 60ms/字 */
    s->last_ms = g->app->now_ms;
    unsigned char c0 = (unsigned char)s->text[s->shown];
    s->shown += c0 & 0x80 ? ((c0 & 0xf0) == 0xe0 ? 3 : 2) : 1; /* UTF-8 安全步进 */
    g->area = (EpdRect){0, 840, 684, 376}; g->want_full = false;
    return GC_EV_DIRTY;
}

static gc_ev_t key(gc_ctx_t* g, int k) {
    hello_state_t* s = (hello_state_t*)g->state;
    if (k == UI_KEY_1) { s->shown = (int)strlen(s->text);      /* 跳过打字 */
        g->area = (EpdRect){0, 840, 684, 376}; g->want_full = false; return GC_EV_DIRTY; }
    return GC_EV_NONE;
}

const gc_plugin_t gc_plugin_hello = {
    .id = "hello", .name = "示例游戏", .cat = GC_CAT_TEXT,
    .launch = launch, .quit = quit, .paint = paint, .key = key, .tick = tick,
};
```

> 复用自检：这个 60 行插件没有任何绘制底层调用（全部 `gc_ui_*`/`ui_text_vc`）、没有 malloc 之外的资源、没有直接刷屏——这就是合格插件的形态。

### 3.3 可用平台能力清单（**只许这些**）

| 能力 | 接口 | 说明 |
|---|---|---|
| 绘制原语 | `ui_kit.h`（ui_text_vc/ui_fill_round_rect/…） | 与全线 UI 同源 |
| 共享游戏 UI | `game_core.h` 的 `gc_ui_*` | 对话框/标题/按钮/打字机/灰度贴图/占位 |
| 图片解码 | `book_cover.h` → `book_image_file_dimensions / _grayscale` | PNG（含灰度）→ 8bit 灰，保比例缩放 |
| 蜂鸣 | `avg_beep.h`（read_pico_buzzer 之上） | 非阻塞音调序列；退出前 `avg_beep_stop()` |
| ZIP 读取 | `zip_reader.h` | 只读、CRC 校验、单条目 ≤8MiB |
| 文件 IO | stdio（`g->pkg_dir` 下） | 存档等写文件也放包目录（缓存目录可写） |
| 内存 | heap_caps（见第 5 节） | 大块一律 PSRAM |

**禁止清单**：直连 epdiy 推屏/整屏刷新（必须走申报）；改全局 rotation；直接操作 PMU/背光/USB；在 paint 中做 IO 或发声；绕过 `gc_launch` 自建第二实例；静态大数组（BSS 有限，见第 5 节）。

## 4. SD 资源目录规范与打包

### 4.1 TF 卡布局（用户视角）

```
/sdcard/games/                       ← 游戏资源根目录
├── avgr-gyakuten-case1.zip          ← 推理 AVG 包
├── avgr-xxx.zip                     ← 同分类可有多个（当前取首个）
├── text-demo.zip                    ← 文字游戏包
├── text-mynovel/                    ← 同名目录=目录直挂（免 zip，开发期友好）
└── bbk-fmj/                         ← BBK 大资源目录直挂（DAT.LIB 数十 MB）
```

### 4.2 命名规则（与 `gc_cat_prefix` 一一对应，新增分类两处同步改）

| 分类 | 包形态 | 命名 | 包根内容 |
|---|---|---|---|
| 推理 AVG | zip**（可目录直挂） | `avgr-<game>-<case>.zip` | `script.txt` + `images/{bg,char}/…png` |
| 文字游戏 | zip（可目录直挂） | `text-<name>.zip` | `story.txt`（+ 可选图片） |
| 步步高 BBK | **目录直挂（标准）** | `games/bbk-<name>/` | `DAT.LIB`、`HZK16`、`ASC16`、`FMJHD.BIN`(可选) |
| 数织（规划） | zip | `nono-<name>.zip` | `puzzles/*.txt` |
| 棋类（规划） | zip | `chess-<name>.zip` | 棋谱/引擎参数 |
| GB（规划） | zip | `gb-<name>.zip` | ROM（≤8MiB/条目） |

规则细节：
- 同前缀下 **zip 优先于同名目录**（挂载确定性）；各分类内按枚举序取第一个包（v1 单包语义）。
- zip **单层解压**：包内文件必须 ≤2 层子目录、单条目 ≤ 8MiB、不加密；超出的大资源一律目录直挂。
- zip 首次挂载解压到 `/sdcard/.gcache/<包名>/`；以 zip 字节数为指纹，**zip 变更自动重解**。缓存目录可写（存档写包目录即可）。
- 隐藏文件（`.` 开头）被忽略；`.gcsize` 是缓存标记，勿手删。

### 4.3 打包工具（仓库自带，Python3 标准库零依赖）

```bash
# 推理 AVG：案件目录 → avgr-gyakuten-case1.zip
python tools/game_pkg.py avgr path/to/case1 --name gyakuten-case1 --out tools/pkgs

# 文字游戏
python tools/game_pkg.py text path/to/mynovel --name mynovel

# BBK 资源校验（不打 zip，打印就绪状态与拷贝指引）
python tools/game_pkg.py bbk path/to/fmj_res
```

产物拷进 TF 卡 `/sdcard/games/` 即生效（进游戏自动重扫，无需重启设备）。

## 5. 内存管理规则

### 5.1 内存分区（ESP32-S3）

| 区域 | 容量 | 用途 | 分配方式 |
|---|---|---|---|
| 内部 RAM（含 DMA/BSS） | 约 300KB 可用 | 栈、小对象、DMA 缓冲 | `malloc`/静态（**受严格约束**） |
| PSRAM（SPIRAM） | 8MB | 游戏数据、图片灰度、脚本、缓存 | `heap_caps_malloc(n, MALLOC_CAP_SPIRAM \| MALLOC_CAP_8BIT)` |

### 5.2 插件分配决策表

| 大小/类型 | 选择 | 例 |
|---|---|---|
| < 4KB 且生命周期=会话 | `calloc`（内部 RAM） | 插件 state 结构 |
| ≥ 4KB 或含图片/脚本 | `heap_caps_malloc(…, MALLOC_CAP_SPIRAM\|MALLOC_CAP_8BIT)` | avgr script 800KB、gtext 剧本、bg 灰度缓冲 |
| 运行期反复加载的图集 | 走 `avg_assets_*`（LRU 上限 8 槽，换场景自动逐出） | 立绘/背景 |
| 常驻大资源（>8MiB） | 不进内存：目录直挂 + 分块随机读 | BBK DAT.LIB |

硬规则：
1. **静态 BSS 大数组禁止**（>32KB 即违规）。参考事故：`avg_script_t` 800KB 误入 BSS 直接链不过。
2. **quit 必须归还全部**（内核只卸包不清私房内存）；对称性自检：grep 插件里每个 malloc/new 对应 free。
3. 峰值约束：单插件会话 PSRAM ≤ 6MB（给系统 UI/浏览器扫描留 2MB 余量）。
4. `launch` 失败路径同样要走 quit 语义（或先全部分配成功再挂 state）。

### 5.3 图片解码内存

单图上限 = 684×830 ≈ 570KB（8bit 灰）；解码走 `book_image_file_grayscale`（临时缓冲由调用方给）。多图场景用 assets LRU（8 槽 ≈ 4.5MB 上限）而不是自己缓存。

## 6. 编译与集成说明

### 6.1 从零环境（全新电脑）

1. 安装 **ESP-IDF v6.1**（官方 Windows Installer 或手动 clone + `install.bat`）。
2. 安装 Python 3.12（IDF 自带亦可）、`D:\esp-tools\python_env` 工具链为项目既有布局，可按需调整。
3. 取得工程源码（本仓库），确认 `D:/esp-idf` 与构建脚本中 IDF 路径一致（或改 `build_takeeasy.ps1` 中的路径）。

### 6.2 集成一个新插件的全部步骤（以 `hello` 为例）

1. **实现插件**：`main/apps/plugins/hello.c` + `hello.h`（§3.2 模板）。
2. **入口薄壳**：新建 `main/apps/app_hello.c`（拷贝 `app_gtext.c` 改名替换两处：include 的插件头 + `app_desc_t app_hello` 字段 title/detail）。
3. **登记构建**：`main/CMakeLists.txt`：
   - SRCS 追加 `"apps/plugins/hello.c"`、`"apps/app_hello.c"`；
